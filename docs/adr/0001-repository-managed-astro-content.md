# Make repository-managed Astro content authoritative

Replace PocketBase with repository-managed Astro content collections for Likes, software and music releases, keeping content and required assets with the project so neither PocketBase nor a replacement database or external CMS is required to build or run the site. This is a content-platform migration, not a redesign: preserve published content, public page URLs and visitor-facing functionality, and keep the public site's appearance identical except for the owner-approved image-generation change below. The owner will edit content files and assets directly and commit them, without a replacement browser-based editor; publication requires a successful build and deployment, with failed builds leaving the previous site live.

Likes and music use a folder per entry with an `index.md`, structured frontmatter and adjacent assets. Software entries may simplify to frontmatter only: shared pages render structured fields, not MDX bodies, and image dimensions come from local originals rather than redundant authored fields. Preserve existing text interpretation rather than introducing Markdown rendering for currently literal text. Give each migrated collection item an explicit slug matching its current readable URL, retain its legacy PocketBase-ID redirect, and keep the slug stable when its title changes; new items also receive explicit slugs.

Use native Astro asset handling rather than retaining PocketBase's publishing machinery. The original migration required unchanged visuals; the owner subsequently accepted native responsive image generation from adjacent originals instead of captured variants, without historical image byte parity. The owner also approved dropping legacy `/published-content/` and `/published-releases/` media URLs and removing their static compatibility copies to simplify the repository; page URLs, legacy page redirects and `/audio/` files remain supported. Migration acceptance still requires reconciling published content with the deployed baseline and verifying page URLs, ordering, interactions and desktop/mobile appearance; byte-identical HTML is not required. Publish plain static `dist/` output to Netlify without the Netlify adapter, retaining blog rules in `public/_redirects` and existing Likes ID redirect pages. These simplifications do not establish migration acceptance or waive separate owner approval for production deployment.

The public repository contains publication-ready content only. Draft support and migration of unpublished records are out of scope; existing unpublished backend data remains untouched. Removing this site's dependency does not authorize shutdown of the shared PocketBase service.
